# TLS, certificate UI, and keystore boundary

This package owns the application's SSL context, X.509 key/trust managers, certificate dialogs, and JKS persistence adapter. It is part of the existing JFTP application, not an independent module. Read the [repository instructions](../../../../../../../AGENTS.md), [Java boundary instructions](../../../../AGENTS.md), the application/session instructions ([jftp](../AGENTS.md)), [TLS and persistence notes](../../../../../../../docs/tls-and-persistence.md), and [brief protocol/certificate modernization options](../../../../../../../docs/security-modernization-options.md) before changing this package. FTPS uses TLS/X.509; SFTP uses SSH and has no built-in implementation here. Adding SFTP requires separate feature scope and SSH host-key verification rather than reusing JKS trust decisions.

Preserve existing FTPS modes, certificate view/install/manage flows, configured keystore paths/passwords, JKS compatibility, and caller-visible failures until isolated fixtures characterize them. The current custom trust path validates only the first certificate's validity, compares only the leaf CN with the host, accepts on user Yes despite failed checks, and does not invoke delegate PKIX validation. Treat these as security defects; a secure correction must validate chains and hostnames correctly. Make the visible override/prompt policy an explicit product decision, retain the separate Install action semantics, and add controlled local FTPS regression coverage before changing it.

Keystore persistence uses raw preference path strings, certificate-only entries for imports, JFTP-number aliases, and direct writes. Do not silently change JKS/PKCS12 format, aliases, passwords, serialized preferences, store locations, or client identity semantics. Keep real user keystores/passwords out of tests and logs. Client-certificate authentication requires private-key entries even though the visible manager currently imports certificates only; any identity-import feature is separate scope.

When an authorized implementation change alters security policy, file format, persistence, APIs, package responsibility, or dependencies, update this file, root and Java-parent instructions, and [TLS/persistence documentation](../../../../../../../docs/tls-and-persistence.md) in the same logical change. No production or test implementation is authorized in the present analysis phase.
