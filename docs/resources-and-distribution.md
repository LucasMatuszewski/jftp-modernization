# Resources, help, and distribution

This is the observed resource/distribution inventory as of 2026-10-06. Binary assets were inventoried by path, file type, and count; their visual content was not treated as source. No build, startup, or tests were attempted in this documentation phase.

The [Windows bootstrap](windows-startup.md) verifies startup resources on the compiled classpath and a real desktop launch, with the original resource roots intact. The archive/launcher inventory below remains historical and unverified; this slice does not repair packaging.

## Resource roots and localization

The POM's explicit Maven resource roots are `src/main/resources`, `src/main/resources_de`, `src/main/resources_zh_TW`, `src/main/images`, and `src/main/help` ([pom.xml](../pom.xml), `<build><resources>`). They have no includes, excludes, filtering, or per-resource encoding overrides. The project source encoding property is UTF-8. Because `<resources>` is explicitly configured, these five roots define the intended resource inputs; there is no explicit test resource customization. Eclipse metadata separately lists each resource/image/help root as a source folder with `excluding="**"`, so Eclipse does not copy these folders as classes by itself. Current documentation-phase nested `AGENTS.md`/`CLAUDE.md` files under `src/main` can also be included by Maven's broad resource roots and by the assembly's root `*.md` pattern. When build configuration is next changed, explicitly exclude agent instructions from the shipped classpath/archive if preserving the product footprint is intended; the descriptor is unchanged in this phase.

The base UI bundle tree contains 57 `.properties` bundles, German contains 57, and Traditional Chinese (`zh_TW`) contains 58. The bundles mirror package paths under `com/myjavaworld/gui`, `com/myjavaworld/jftp` (including `ssl`), and `com/myjavaworld/util`. Bundle names carry locale suffixes such as `_de` and `_zh_TW`; JavaHelp content itself is English-only. The README identifies English, German, and Traditional Chinese as the shipped UI languages. The Chinese tree additionally has `InstallLicenseDlg_zh_TW.properties` without a corresponding base bundle, so this should be checked against Java resource lookup/source ownership before pruning. The README and resources also mention `JFTPApplet`, which is a compatibility clue, not proof that the applet remains runnable.

All three complete bundle trees are listed in the coverage ledger. Most default/German/Chinese bundle sets align by basename. There are known shape differences worth preserving and reviewing: Chinese has the additional install-license bundle; the Traditional Chinese local and remote filter descriptions use a single-line escaped HTML value while the default bundles express the same content over continued lines; a naive line parser sees different pseudo-keys because `=` is escaped inside HTML attributes. Property continuation and escaping syntax must be preserved when editing. German text includes legacy non-ASCII content; confirm actual source encoding and rendered strings before converting the bundle format or applying a blanket encoding rewrite. Do not claim perfect translation parity based only on filename counts.

The two original tracked `src/test` files at baseline `14e62ce` are empty `.gitkeep` placeholders. No test classes or test fixtures currently establish a resource contract; this documentation phase adds test-scope agent instructions only.

## Images and help delivery

`src/main/images/com/myjavaworld/jftp` contains 50 binary application assets: 38 GIF, 11 PNG, and 1 macOS ICNS icon (counts classified from tracked content). These include small toolbar/action icons, file/folder/host indicators, JFTP size variants, and splash art. Several newer PNG variants share names with legacy GIF assets; keep both until source references and platform selection are verified. `src/main/help/helpset/content/images` and `.../sessions/images` together contain 46 GIFs. The help set also contains a large screenshot in GIF and PNG formats. Across all owned paths there are 98 binary assets total: 85 GIF, 12 PNG, and 1 ICNS. Exact per-path inventory is in the coverage ledger.

JavaHelp is rooted at [src/main/help/helpset/helpSet.xml](../src/main/help/helpset/helpSet.xml). It declares `index` as home, loads `map.xml` and `toc.xml`, provides a table-of-contents view and leaves the search view commented out. The map and TOC route help topics for introduction, UI, connection, transfer, local/remote file operations, sessions, favorites, security, preferences, keyboard shortcuts, tips, FAQ, support, feedback, credits, and the license. In [map.xml](../src/main/help/helpset/map.xml), the local open target currently points to `content/content/local/open.html` although the tracked topic is `content/local/open.html`; this looks like a broken help link and should be confirmed/fixed with a JavaHelp launch check. Preserve the help IDs and paths because application help actions can refer to those identifiers. The help folder includes its own Apache 2.0 license text.

Help HTML is legacy HTML 4 and links locally to sibling topics, CSS, and images. The content describes FTP/FTPS connection setup, user-facing keyboard/menu actions, transfer options, filtering, file editing, and operating-system-specific behavior. It is part of the shipped product, not disposable build output. Help search database files are not tracked; the search view is disabled in the helpset.

## Distribution and launch behavior

The POM creates an executable jar manifest for `com.myjavaworld.jftp.JFTPApplication` and writes dependency references with a `lib/` classpath prefix. The assembly descriptor produces a base-directory distribution as zip, directory, and tar.gz, puts dependency artifacts under `lib/`, puts project jars at the distribution root, copies root text/Markdown documents, and filters scripts from `${project.build.scriptSourceDirectory}`. The [Windows batch launcher](../src/main/scripts/jftp.bat) and [POSIX shell launcher](../src/main/scripts/jftp.sh) invoke the jar from `lib/`, which disagrees with the descriptor's root placement of the project jar. The POM does not set `project.build.scriptSourceDirectory`; Maven's default location and filtered result have not been confirmed. Therefore package layout, script expansion, and launch are unverified. Both scripts currently have the same one-line `java -jar` command and no extra JVM flags or OS-specific setup.

No standalone runtime, installer, native launcher, checksums, SBOM, release automation artifact, or vendored jar is tracked. The assembly's transitive dependency set means the distribution includes all resolved runtime dependencies, but its exact contents cannot be documented until Maven resolves them. Keep the Maven central/custom-repository resolution results and licensing review with any future dependency change. The assembly's unfiltered root docs include `*.txt` and `*.md`; this should continue to include both top-level legal files, while the separate help content license remains embedded in help resources.

## Safe resource modernization

Preserve resource-relative paths and locale suffixes while changing Java, Maven, or packaging. Make help map/TOC references and image lookups explicit characterization checks; fix the suspected local-open path only alongside such a check. Compare localized bundle keys and displayed text using Java Properties continuation rules rather than raw line counts. Convert encodings only after capturing exact translations and verifying runtime lookup behavior. Keep both legacy and newer icon variants until all references and OS selection paths are known.

Any behavior or path change requires updating this document and the relevant root/nested `AGENTS.md` instructions in the same change. The per-file read and binary inventory is [build-resources-coverage.txt](analysis/build-resources-coverage.txt).
