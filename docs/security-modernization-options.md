# FTP, FTPS, SFTP, and certificate direction

Research checked 2026-10-06. Candidates only; no new feature is authorized.

- **Current protocols:** built-in modes cover plain FTP (no TLS) and FTPS (SSL-if-available, explicit, implicit); FTPS data may be unencrypted. No in-tree SSH/SFTP is evidenced, though a reflective custom FTP client could add protocols. FTPS uses TLS and the app's X.509/JKS trust path ([RFC 4217](https://www.rfc-editor.org/rfc/rfc4217)); SFTP runs over SSH and uses SSH host-key trust ([RFC 4251](https://www.rfc-editor.org/rfc/rfc4251)).
- **Asset inventory:** tracked metadata has zero certificate/key/store suffix matches (`.pem`, `.crt`, `.cer`, `.der`, `.p12`, `.pfx`, `.jks`, `.keystore`, `.pub`, `.key`, `.p7b`, `.p7c`). An existence-only check on 2026-10-06 found default profile files `~/.jftp/data/serverCertificates.jks` and `clientCertificates.jks` absent. No contents were read; system stores, custom paths and other locations were not inventoried. The UI imports X.509 certificate entries, not private keys.
- **FTPS direction:** prefer TLS 1.3, retain TLS 1.2 for interoperability, and prohibit TLS 1.0/1.1 ([RFC 9846](https://www.rfc-editor.org/info/rfc9846/), [RFC 8996](https://www.rfc-editor.org/rfc/rfc8996/)). The `SSL` algorithm alias is not proof of SSLv3 configuration; negotiated TLS is unknown without a handshake. Correct chain/hostname validation and decide visible trust-prompt changes; do not globally weaken TLS for legacy servers.
- **FTP library option:** verify FTPAPI 3.0.0 provenance, API, license and redistribution rights first. If replacement is needed, Apache Commons Net **3.13.0** is an official Java 8+ FTP/FTPS candidate. Its FTPS hostname verification is off by default, so enable and test it. Compare parsers, callbacks, ASCII, passive/active modes and data-channel protection. ([release](https://commons.apache.org/proper/commons-net/changes.html), [Java requirement](https://commons.apache.org/proper/commons-net/download_net.html), [FTPS API](https://commons.apache.org/proper/commons-net/apidocs/org/apache/commons/net/ftp/FTPSClient.html))
- **Optional SFTP:** Apache MINA SSHD **2.20.0** is the latest stable 2.x release checked; 3.0.0 is in development and API-incompatible. If separately authorized, assess host-key persistence/change prompts, authentication, SFTP operations, JDK, license and transitive dependencies. New product functionality, outside modernization; do not bundle with FTPAPI replacement. ([releases](https://mina.apache.org/downloads-sshd.html), [project](https://mina.apache.org/sshd-project/), [2.20.0 notes](https://mina.apache.org/sshd-project/download_2.20.0.html))
