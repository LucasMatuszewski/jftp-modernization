# Application workflows and observable contracts

This document describes the current application behavior from source inspection. It records current behavior and explicit compatibility questions; it does not claim that the build, application, or tests were run. Paths below are relative to this document.

## Launch, window and sessions

The desktop entry point is `JFTPApplication.main`. It loads the saved locale and look and feel, conditionally registers the macOS About/Preferences/Quit handlers and full-screen support, then creates and displays `JFTP` with one initial session ([JFTPApplication.java](../src/main/java/com/myjavaworld/jftp/JFTPApplication.java#L22)). A separate `JFTPApplet` launcher creates a desktop frame in applet mode when its button is clicked ([JFTPApplet.java](../src/main/java/com/myjavaworld/jftp/JFTPApplet.java#L30)). Browser applet execution is a legacy compatibility question, especially for current JDK/browser support; do not silently delete or claim it runs in a modern browser.

`JFTP` manages multiple tabbed `FTPSession`s and menu/toolbar state follows the currently selected tab ([JFTP.java](../src/main/java/com/myjavaworld/jftp/JFTP.java#L136), [JFTP.java](../src/main/java/com/myjavaworld/jftp/JFTP.java#L168)). Closing a tab closes its session and removes it. Exit closes every session, saves frame bounds and preferences, disposes the frame, and calls `System.exit(0)` only for desktop mode ([JFTP.java](../src/main/java/com/myjavaworld/jftp/JFTP.java#L197)). On first window open the frame maximizes if no stored bounds exist; it starts the updater when the preference is enabled ([JFTP.java](../src/main/java/com/myjavaworld/jftp/JFTP.java#L157)).

The main window builds six menus in this order: FTP, Local System, Remote System, Transfer Mode, Tools, and Help ([JFTP.java](../src/main/java/com/myjavaworld/jftp/JFTP.java#L466)). The toolbar provides common session, connect/reconnect/disconnect, transfer, local/remote create/navigate/rename/delete, favorite/certificate management, and help shortcuts ([JFTPToolBar.java](../src/main/java/com/myjavaworld/jftp/JFTPToolBar.java#L86)). Menu and toolbar enablement depends on connection and selection state, and should remain coherent with active-tab switching.

## Connection lifecycle and remote hosts

The connect action opens a connection dialog initialized from the current session host, or from global FTP client, listing parser, passive mode and TLS defaults. It has General, Security, Advanced and Commands tabs. Required host/user/password are checked using trimmed text, and port accepts 0 through 65535; approved values retain their original whitespace. Blank user/password populate as `anonymous` and the global email preference. The implicit-SSL port is validated only when implicit SSL is selected. Advanced settings preserve implementation class choices, initial local/remote directory text, passive mode and raw post-login commands ([UI and browser details](ui-and-browser-details.md#connection-and-preference-dialogs)). On approval, `FTPSession.connect` chooses the configured FTP client and listing parser by class name, applies passive mode, timeout, buffer size and TLS settings, attaches event listeners, opens the control connection, authenticates, sends host-specific commands, enters the configured initial remote directory, and lists it ([ConnectAction.java](../src/main/java/com/myjavaworld/jftp/actions/ConnectAction.java#L43), [FTPSession.java](../src/main/java/com/myjavaworld/jftp/FTPSession.java#L617)). The session may prompt before replacing an existing connection; reconnect reuses the last `RemoteHost` ([FTPSession.java](../src/main/java/com/myjavaworld/jftp/FTPSession.java#L593), [FTPSession.java](../src/main/java/com/myjavaworld/jftp/FTPSession.java#L701)).

The external client is FTPAPI's `FTPClient`. Source call sites cover `connect`, `login`, `disconnect`, `list`, `setWorkingDirectory`, `upload`, `download`, `createDirectory`, `createFile`, `rename`, `delete`, `executeCommand`, and `abort`. SSL/TLS modes are no SSL, SSL if available, explicit SSL and implicit SSL; the client also has a data-channel-unencrypted setting ([FavoritePropertiesDlg.java](../src/main/java/com/myjavaworld/jftp/FavoritePropertiesDlg.java#L64), [FTPSession.java](../src/main/java/com/myjavaworld/jftp/FTPSession.java#L634)). This is FTPS, not SFTP: no SSH/SFTP client or SFTP call path exists in the inspected application sources.

The connection transcript reports commands, replies and connection/error status. The status bar displays whether the FTP API reports the connection as secured, plus transfer/list progress, speed and elapsed time ([FTPSession.java](../src/main/java/com/myjavaworld/jftp/FTPSession.java#L518), [StatusBar.java](../src/main/java/com/myjavaworld/jftp/StatusBar.java#L87)). SSL context construction calls `JFTPSSLContext.getSSLContext(jftp, host)` before the socket connection. Trust, certificate import and persistence behavior is detailed in [TLS and persistence](tls-and-persistence.md).

## Browser and file workflows

Each session presents local and remote file panes side by side above the protocol/status transcript. The local side starts from the saved local directory, falling back to the platform's default directory if it is missing. Connection may replace that starting directory with a host favorite's initial local directory. The remote side is populated after connect and changes with the FTP working directory. Local and remote filters are per-session and clearing a filter restores an unfiltered listing. Pane behavior includes multi-selection, header sorting, double-click/Enter navigation, keyboard delete, directory/link navigation, selection totals, and right-click context menus. A selected-row popup retains the current multi-selection; a blank-area popup clears it. Sorts act on the underlying data array without a separate row sorter, and descending order also places directories after files ([UI and browser details](ui-and-browser-details.md#browser-rows-selection-and-navigation)).

The Local System menu and its popup offer open, edit and print; create local file/directory; change directory; rename and recursive delete; apply/clear filter; refresh; properties; select all and invert selection. The popup also offers upload, upload as, and zip-and-upload. The Remote System menu and its popup offer open/edit/print; create remote file/directory; change directory; rename/delete; raw HELP/STAT/SYST/NOOP or custom server commands; apply/clear filter; refresh; properties; select all and invert selection. The remote popup also offers download, download as, and download-and-unzip ([LocalSystemMenu.java](../src/main/java/com/myjavaworld/jftp/LocalSystemMenu.java#L46), [RemoteSystemMenu.java](../src/main/java/com/myjavaworld/jftp/RemoteSystemMenu.java#L44), [UI and browser details](ui-and-browser-details.md)). Open on a directory changes that pane's working directory. Local file open/edit/print delegates to `java.awt.Desktop`; remote file open/edit/print downloads a temporary copy and delegates to Desktop. For monitored remote edits, the application prompts to upload the changed temp file to its original remote path.

Local file operations act on the local filesystem; remote operations use FTPAPI. Delete actions request confirmation. Remote properties support permission changes through the server's `SITE CHMOD` command, including a recursive path ([JFTP.java](../src/main/java/com/myjavaworld/jftp/JFTP.java#L342), [FTPSession.java](../src/main/java/com/myjavaworld/jftp/FTPSession.java#L1074)). The file browser also supports drag/drop: dropping remote selections onto the local pane triggers download, and dropping local selections onto the remote pane triggers upload ([DnDTransferHandler.java](../src/main/java/com/myjavaworld/jftp/DnDTransferHandler.java#L55)). Local filtering uses regexes against names and optional lenient date bounds. A current edge is that exclusion mode can include hidden files when the hidden checkbox is off; directories generally pass the file filter unless an early hidden-directory check rejects them. Remote filters have no hidden-file option. File/property dialogs validate required text but retain some untrimmed path/name input; remote property traversal uses the active filter and must restore the prior working directory ([UI and browser details](ui-and-browser-details.md#local-and-remote-filters), [UI and browser details](ui-and-browser-details.md#file-dialogs-and-properties)). Treat these behaviors as current observations and decide any correction explicitly.

## Transfer and archive workflows

The Transfer Mode menu selects automatic extension mapping, ASCII or binary per session ([TransferModeMenu.java](../src/main/java/com/myjavaworld/jftp/TransferModeMenu.java#L44)). Automatic mode uses the extension map in `JFTPPreferences`, then the configured default transfer type when no extension mapping is found ([FTPSession.java](../src/main/java/com/myjavaworld/jftp/FTPSession.java#L197)). The default transfer type is binary; common source, markup, shell, config and text file extensions default to ASCII ([JFTPPreferences.java](../src/main/java/com/myjavaworld/jftp/JFTPPreferences.java#L104)).

FTP menu transfers include download/upload selected items, download as/upload as a renamed destination, download-and-unzip a selected ZIP, and zip selected local files then upload. Recursive directory operations create matching directories and walk children subject to the pane filter. Abort requests `FTPClient.abort()` and prevents later items in the recursive selection loop; the data connection callback resets status and reports that the transfer was aborted ([AbortAction.java](../src/main/java/com/myjavaworld/jftp/actions/AbortAction.java#L44), [FTPSession.java](../src/main/java/com/myjavaworld/jftp/FTPSession.java#L566)). Transfers update the progress bar, speed and elapsed time. If an FTP or local I/O operation fails, the session records an error; no separate transactional rollback is evident in the application orchestration.

Remote edit/open/print share a temp-file download path. ZIP extraction has its own progress events and optional post-extraction archive deletion. ZIP creation uses the local selection, the current local filter and local working directory for relative paths; after upload it can delete the local ZIP ([ZipAndUploadAction.java](../src/main/java/com/myjavaworld/jftp/actions/ZipAndUploadAction.java#L59)). ZIP traversal safety is a known future security-fix area; do not represent unsafe legacy behavior as a required contract.

## FTP command and tools workflows

The remote Execute submenu sends HELP, STAT, SYST and NOOP through `FTPSession.executeCommand`; Other opens a custom-command dialog. The session runs commands on a worker but filters out transfer/data and directory-changing prefixes (`LIST`, `NLST`, `RETR`, `STOR`, `STOU`, `APPE`, `PASV`, `PORT`, `DATA`, `CWD`, `CDUP`) from the custom command path ([JFTP.java](../src/main/java/com/myjavaworld/jftp/JFTP.java#L243), [FTPSession.java](../src/main/java/com/myjavaworld/jftp/FTPSession.java#L1450)). Existing filtering case-normalizes the submitted command for prefix checks. Keep protocol-level and custom-command behavior distinct when replacing FTPAPI.

Tools contains add current connection to favorites, manage favorites, manage certificates, and preferences. macOS hides Exit and Preferences from these menus because the native application menu is used; macOS adapter callbacks route About, Preferences and Quit to the ordinary dialogs/frame exit. The active `OSXAdapter` uses reflection, while `OSXAdapterOld` directly imports Apple's legacy `com.apple.eawt` API ([OSXAdapter.java](../src/main/java/com/myjavaworld/jftp/OSXAdapter.java#L48), [OSXAdapterOld.java](../src/main/java/com/myjavaworld/jftp/OSXAdapterOld.java#L76)).

Help has contents, tips, FAQ, support, feedback and About. `JFTPHelp2` loads the JavaHelp `helpset/helpSet.xml` resource and wires help IDs to menus/buttons/dialogs ([JFTPHelp2.java](../src/main/java/com/myjavaworld/jftp/JFTPHelp2.java#L43)). Current help map paths and external endpoints should be verified during a later UI launch; do not infer endpoint availability from source strings.

`AutoUpdater` is started after a 15-second delay when enabled. It reads `latestVersion` and `infoURL` from `http://www.jMethods.com/software/jftp/update.properties`, compares version strings lexicographically, and shows an update message. On error it prints a stack trace and retries after five minutes ([AutoUpdater.java](../src/main/java/com/myjavaworld/jftp/AutoUpdater.java#L31)). Endpoint status, transport security, version ordering and product policy are unresolved questions; a modernization should preserve an explicit update preference until the endpoint/feature decision is made.

## Preferences and favorites

Preferences include connection general and advanced settings, SOCKS proxy, security/certificate stores, transfer modes, regional settings, UI themes/toolbars, and software update checks. Save validates the first seven panels then invokes all eight save methods; Cancel does not save, though Software Updates “Check Now” starts an updater immediately even before Save/Cancel. Restore Defaults repopulates every panel from a new default bean. The locale panel currently selects the JVM default locale when populated instead of the stored preference ([PreferencesDlg.java](../src/main/java/com/myjavaworld/jftp/PreferencesDlg.java#L100), [PreferencesDlg.java](../src/main/java/com/myjavaworld/jftp/PreferencesDlg.java#L288), [UI and browser details](ui-and-browser-details.md#connection-and-preference-dialogs)).

Favorites hold host label/address/port, user/password/account, FTP client and listing parser classes, initial local/remote directories, passive mode, login-time commands and SSL/data-channel choices. The manager sorts favorites, rejects duplicate names, supports add/edit/delete and connects the selected host in the active session (creating a session if none exists). `JFTP.DATA_HOME` is `${user.home}/.jftp/data`; global preferences and favorites are Java serialized files there. `JFTPPreferences` declares `serialVersionUID = 4316033315068041786L`, `RemoteHost` declares `-3213664402994404410L`, and `Favorite` declares `-8742993458243896488L`. The top-level saved containers are `JFTPPreferences` and the favorites list; `JFTP`/`FavoritesManager` define no additional explicit serialized-container version identifier. `RemoteHost.password` is a `String`; `FavoritesManager` wraps the favorite list in a fixed-key AES `SealedObject` with plaintext fallback. Preference proxy and certificate-store passwords are char arrays serialized without obfuscation. These are current persistence facts, not acceptable secrets-storage goals. Use only synthetic fixture state in tests ([JFTP.java](../src/main/java/com/myjavaworld/jftp/JFTP.java#L68), [JFTP.java](../src/main/java/com/myjavaworld/jftp/JFTP.java#L512), [FavoritesManager.java](../src/main/java/com/myjavaworld/jftp/FavoritesManager.java#L112), [JFTPPreferences.java](../src/main/java/com/myjavaworld/jftp/JFTPPreferences.java#L40), [RemoteHost.java](../src/main/java/com/myjavaworld/jftp/RemoteHost.java#L39), [Favorite.java](../src/main/java/com/myjavaworld/jftp/Favorite.java#L25)).

## Threading, errors and known behavior questions

`FTPSession` uses the project-owned worker class for blocking network/filesystem tasks and usually refreshes UI state in `finished()`. FTP listener callbacks can also update Swing status controls directly on the callback thread. Transfer timers update progress, elapsed time and speed. Local rename is synchronous. Test behavior at operation boundaries and status/callback effects; do not preserve thread implementation as a contract. Replacing the worker or marshaling callbacks is a distinct concurrency phase because ordering, cancellation, UI refresh and modal certificate prompts are observable.

Current source questions/defects to retain in planning: legacy applet deployment is not established; `OSXAdapterOld` binds to removed/platform-specific APIs; updater uses plain HTTP and lexical versions; favorite storage uses a fixed key; preferences serialize passwords; and ZIP extraction needs explicit traversal safety. Determine user/platform support and desired fixes before changing these paths. Application behavior should be reconciled with [architecture](architecture.md), [regression-test design](regression-test-design.md), [UI and browser details](ui-and-browser-details.md), [TLS/persistence](tls-and-persistence.md), and [resources/distribution](resources-and-distribution.md).
